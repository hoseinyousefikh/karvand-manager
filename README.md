## پاسخ به سوالات Git

### 1. چرا برای قابلیت‌های مختلف پروژه چند Commit جداگانه ثبت کردیم؟

برای اینکه تاریخچه پروژه مرتب باشد و هر Commit یک قابلیت یا تغییر مشخص را نشان دهد. این کار باعث می‌شود پیدا کردن و برگرداندن تغییرات راحت‌تر باشد.

### 2. Git Stash در این پروژه چه کاربردی داشت؟

در این پروژه از `git stash` استفاده نکردیم. کاربرد آن ذخیره موقت تغییرات بدون Commit است تا بتوانیم موقتاً روی کار دیگری کار کنیم.

### 3. چرا فایل `debug.log` را وارد Git نکردیم؟

چون فایل‌های Log معمولاً جزو کد اصلی پروژه نیستند و ممکن است مرتب تغییر کنند. بنابراین بهتر است با `.gitignore` از Git خارج شوند.

### 4. تفاوت `git push` و `git pull` چیست؟

`git push` تغییرات Commit شده را از کامپیوتر به GitHub ارسال می‌کند.

`git pull` تغییرات موجود در GitHub را دریافت کرده و با نسخه محلی ترکیب می‌کند.

### 5. Merge Conflict چه زمانی ایجاد می‌شود؟

وقتی دو تغییر متفاوت روی یک قسمت از یک فایل انجام شده باشد و Git نتواند تشخیص دهد کدام تغییر باید باقی بماند.

### 6. یک مثال ساده از Merge Conflict

فرض کنیم در `app.py` یک نفر نوشته باشد:

```python
print("سیستم مدیریت کاروند")
```

و شخص دیگری همان خط را به شکل زیر تغییر داده باشد:

```python
print("مدیریت کاروندها")
```

هنگام ترکیب تغییرات، Git نمی‌تواند یکی را به‌صورت خودکار انتخاب کند و Merge Conflict ایجاد می‌شود. سپس باید تغییر موردنظر را انتخاب و Conflict را برطرف کنیم.
